# Чтение файлов моделью с сервера

Черновик реализации, 24.09.2026. Один серверный диалог с одной моделью: короткий старт → чтение файлов → проверка → результат. Здесь описан будущий механизм; приложение пока не изменено.

## Вход

| Часть | Содержание |
| --- | --- |
| Доверенная инструкция | [start.md](drafts/task-16/start.md), версия пакета `task16-v3` |
| Данные задачи | Условие, известный математический ответ, фото; индивидуальные критерии при наличии |
| Файлы | Восемь виртуальных имён из [таблицы пакета](drafts/task-16/README.md). Имена `feedback.md` и `advice.md` сервер связывает с общими файлами в `drafts/` |
| Изоляция данных | Текст ученика внутри явных границ; фотографии помечены как работа ученика |

«Папка модели» — таблица разрешённых имён на сервере. Настоящего доступа к рабочему каталогу модели не требуется. `start.md` передаётся сразу; остальные тексты возвращаются по вызову инструмента. В каждом запуске используется неизменный снимок пакета.

## Инструмент

`read_file({"path":"criteria.md"})` → текст UTF-8 либо ошибка чтения. Разрешены только восемь имён таблицы; произвольные пути, URL и файлы для человека не доступны. Сервер заранее связывает имя с проверенным файлом снимка. Запись, shell и поиск не нужны.

## Цикл

1. Отправить старт, данные задачи, фото и описание `read_file`.
2. Получить `tool_calls`: сохранить сообщение модели и ID вызовов; прочитать запрошенные разрешённые файлы.
3. Добавить результат каждого чтения как `role=tool` с соответствующим `tool_call_id`. Продолжить тот же диалог с полной историей, включая фото.
4. Повторять до финального ответа. Несколько чтений в одном ходе допустимы. Непустой текст вместе с `tool_calls` ещё не является финалом.
5. До принятия финала проверить, что прочитаны все восемь обязательных файлов. При пропуске вернуть одно сообщение с недостающими именами; повторное нарушение завершить ошибкой сборки, без оценки ученику.

Предлагаемые пределы прототипа: 10 ходов модели, 12 чтений, 32 КиБ на файл, 128 КиБ суммарно. Это ограничения сервера, не характеристики модели. Размер снимка проверять заранее; не усекать инструкции. Общий deadline и лимит вывода задаются конфигурацией; повторные попытки входят в deadline.

## Результат

Вернуть `analysis` и `grading` по одноимённым файлам. Пустой ответ, обрыв или ошибка инструмента не становятся оценкой 0. Для S01–S03 политика результата пока не принята; до её определения эти случаи сами по себе не задают числовой итог. Независимое установленное основание для 0 применяется по `grading.md`.

В интеграции сервер проверяет структуру и балл; сохраняются разделение `LLMVerdict` / `GradeResponse` и постобработка. Если используется пара оценок, сохраняются правила `base >= presentation` и классификация `is_defensible` в анализе. Изменённому сервером баллу должны соответствовать объяснение и советы.

## Необходимые изменения приложения

| Сейчас | Нужно |
| --- | --- |
| `app/llm/types.py`: роли `system/user/assistant`, текстовый `ChatResponse` | Типы tool-вызова/ответа, `tool_call_id`, `tool_calls`, допустимый `content=null` |
| `ChatRequest` не объявляет инструменты | Явный контракт `tools` |
| `openai_provider.py` извлекает текст | Сохранять tool-вызовы и требуемые провайдером поля продолжения; reasoning не принимать за финальную оценку |
| Проверка использует готовые шаблоны | Небольшой цикл диалога и чтение снимка по разрешённым именам |

Новый сервис и отдельные агенты на сервере не требуются. Файловое чтение не должно блокировать обработчик.

## Модель и проверка

В `.env.example` указаны `deepseek-v4-flash` и `deepseek-v4-flash-vision-exp`. Точный model ID и endpoint выбираются перед реализацией. Официальная документация описывает [цикл tool calling](https://api-docs.deepseek.com/guides/tool_calls/); выбранный endpoint должен принимать изображения и инструменты в одном диалоге. Поля продолжения thinking сохраняются по контракту провайдера. Краткость пакета — требование к ясности, а не утверждение о малом контексте модели.

Offline-проверки: preview стартового сообщения и снимка; один и несколько вызовов чтения; сохранение истории/ID/фото; недоступное имя; лимиты и повторное чтение; отсутствующие обязательные файлы; пустой/оборванный ответ; валидация результата. Применять mock, не платный provider. Экспертные баллы из эвалов не включать в доступные файлы.
