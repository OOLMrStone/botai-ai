# Контекст работы над grading-v2

Это инструкции редактору и агентам. Не передавать этот файл модели, проверяющей ученика. Обновлять при новых существенных замечаниях; отменённые решения оставлять только в явно обозначенной истории.

## Цель и текущий объём

Приблизить проверку фото к обоснованной оценке эксперта ЕГЭ. Сейчас работаем над неравенствами: папка `task-16`, источник ФИПИ-2026 — задание 15. Готовим короткий стартовый промпт, предметные файлы и минимальную спецификацию их чтения моделью с сервера. Рабочий сервис не считать образцом новой схемы; его изменение отделять от подготовки документов.

## Что считается хорошим документом

| Требование | Практическое действие |
| --- | --- |
| Один пункт — одна ошибка | Разделять разные причины: потерю допустимых значений и использование недостижимых значений замены, знак интервала и знак самого нуля |
| Справочник структурирован | Использовать тематические таблицы. Не ставить вводные рассуждения сверху или поясняющие абзацы между таблицами |
| Общие инструкции имеют отдельное место | Роль, приоритет критериев, чтение зачёркнутого — в `start.md`. Определения и общие правила классификации — в `rules.md` |
| Уточнение — исключение | Оставлять его, только если без него возникает другой балл или другая классификация. Нужное: вычисление в ОДЗ относится к открытому S01. Лишнее: повторять независимость причин под каждой таблицей |
| Разные ошибки не смешаны | Потеря допустимой граничной точки — отдельная строка; не приписывать её к незавершённому решению |
| Пример конкретен | Вместо «неверно учтено основание между 0 и 1» показать ошибочный переход с основанием 1/2. Начинать пример словом «например» |
| Нет учебника вместо справочника | Не повторять общеизвестные формулы и доказательства без наблюдаемой необходимости для проверки |
| Открытое решение видно | S01–S03 содержат `<решение не принято>`. Не назначать им балл через соседнее общее правило |
| Ручные правки сохраняются | Перед новой редакцией читать текущий файл. Не возвращать удалённые пояснения из старой копии |
| Код однозначен | После декомпозиции обновлять ссылки и таблицу соответствия. Исторические коды маркировать версией |

Удаление хорошего уточнения должно ломать конкретный контраст. Если нельзя назвать, какую ошибочную оценку предотвращает фраза, её следует удалить или вынести из справочника. Количество полезных правил важнее количества текста; краткость не означает смешивание разных случаев.

## Какие вопросы полезны

Высоко оценены вопросы с конкретной короткой работой и точной границей оценки: лишнее условие ОДЗ, ложная ОДЗ при правильном ответе, ложный «⇔» после отбора, переписывание верного ответа, отсутствие возврата из замены. Предпочитать минимальные пары с одним изменением. Не задавать общий вопрос «а как отличить?» без наблюдаемого различия. Не превращать интерпретацию одного эксперта о причинах ошибки в определение всей категории.

## Установленные решения

- Вычислительная ошибка — неверно полученное число в результате верного действия.
- Одна такая ошибка при остальном верном решении — 1; несколько независимых — 0. Случайное совпадение ответа не меняет это правило; S01/S02 остаются открытыми исключениями.
- Зачёркнутые записи не читать и не проверять. Незачёркнутую замену проверять.
- S01: вычислительная ошибка в ОДЗ. S02: вычисление с ложным «⇔». S03: полностью верное решение с неверно переписанным ответом. Все три открыты.
- Отсутствие названия рационализации и избыточного условия при верной ОДЗ не является ошибкой.
- Значительные пропуски вычислений, из-за которых даже при благожелательном чтении нельзя проследить логику переходов, — 0. Незначительные пропуски при прослеживаемой логике, верных этапах и ответе — не ошибка. Прежняя фраза о голословных утверждениях удалена по просьбе пользователя; не возвращать её.
- Эксперты — учителя и авторы опубликованных экспертных разборов. Агентские ответы не являются голосами экспертов.
- Текущие 21 работы ФИПИ — рабочие эвалы. Новый набор не является условием первого запуска. Скрытые экспертные ответы не передавать проверяемой модели.
- Объяснение оценки и советы ученику — отдельные результаты. Совет помогает решать вернее и избегать более строгой трактовки записи, но не повышает выставленный балл.

## Рецензирование каждой содержательной редакции

1. Отправить файлы и актуальные требования двум отдельным агентам: рецензенту структуры и рецензенту лишних уточнений.
2. Первый проверяет атомарность, полноту, статусы S и соответствие экспертным основаниям. Второй проверяет каждое уточнение вопросом «какой неправильный вывод возникает без него?».
3. Исправить реальные замечания и повторно отправить изменённые файлы. Не добавлять пояснение только потому, что рецензенту хочется более длинного текста.
4. Проверить все ссылки, уникальность кодов и отсутствие скрытых оценок для S01–S03. Отдельно проверить сохранность ручных правок.

В этом проекте используются агенты Astra с низкой глубиной рассуждения, согласно предпочтению пользователя. Рецензии запускаются в ходе работы; не обещать автономное наблюдение за файлами между сообщениями.

## Исследование и реализация

Первичные критерии и разборы экспертов отделять от учебных советов и собственной гипотезы. Указывать, что реально прочитано/просмотрено. Балл другого задания не переносить автоматически на неравенства.

Серверная идея: один диалог модели, короткий старт и `read_file` для разрешённых файлов. Имя файла в тексте само по себе не даёт модели доступ к диску. Не добавлять лишние сервисы и обязательные стадии. Размер контекста и поддержку изображений/инструментов проверять по документации конкретного провайдера; не выдавать предположение за ограничение модели.

Правила корневого AGENTS.md сохраняются. Платные модельные вызовы без отдельного запроса не запускать. История и заметки для человека не входят в серверный набор файлов модели.
