# Локальная проверка через DeepSeek API

Приложение запускает микросервис на компьютере и открывает форму в браузере.
Прикрепите одно фото с условием и правильным ответом (эталонный разбор
необязателен), затем отдельно от одной до четырёх фотографий работы ученика.
Проверка использует действующие `app/grading/`, инструменты и валидатор;
описание их контракта — в [grading/service.md](grading/service.md).
Запросы идут прямо на `https://api.deepseek.com/v1`, минуя сервер BotAI,
Selectel и шлюз разработчика. Интернет нужен только для вызовов DeepSeek API.

## Как запустить готовую программу

Распакуйте папку приложения или положите исполняемый файл в корень своей
рабочей структуры. На Windows откройте `BotAI-Local.exe`. На macOS держите
`BotAI-Local` и `Start.command` рядом и откройте `Start.command`.
Браузер откроется автоматически; адрес также появится в терминале.
Программа слушает только локальный адрес `127.0.0.1`.

Окно программы оставьте открытым во время проверки. Закрытие вкладки браузера
не останавливает сервер. Завершите приложение через Ctrl+C в терминале
или закройте его окно. Поддержан только номер **16** проекта — неравенства,
ФИПИ-2026 №15, оценка 0–2. Папки других номеров пока резервируют структуру.

Два допустимых расположения файлов:

```text
Рабочая папка/                     Рабочая папка/
├── BotAI-Local[.exe]              ├── BotAI-Local[.exe]
├── Start.command (macOS)          ├── Start.command (macOS)
└── prompts/                      └── tasks/
    ├── common/                       ├── common/prompts/
    │   ├── main.md                   │   ├── main.md
    │   ├── analysis.md               │   ├── analysis.md
    │   ├── grading.md                │   ├── grading.md
    │   └── response-format.md        │   └── response-format.md
    ├── 14/                           ├── 14/prompts/
    ├── 15/                           ├── 15/prompts/
    ├── 16/                           ├── 16/prompts/
    │   ├── ocr.md                    │   ├── ocr.md
    │   ├── criteria.md               │   ├── criteria.md
    │   └── popular_mistakes.md       │   └── popular_mistakes.md
    └── 17/ … 20/                     └── 17/prompts/ … 20/prompts/
```

Исполняемый файл определяет рабочую папку по своему расположению, независимо
от того, из какой папки его запустили. Параметр `--workspace` позволяет указать
другую папку. При наличии `prompts/16` выбирается вся серверная структура
`prompts/`; неполный пакет вызывает понятную ошибку, а файлы двух структур
не смешиваются. Семь промптов остаются обычными локальными файлами, их можно
редактировать без пересборки программы. Перед новой проверкой обновите форму.

Модель получает содержимое разрешённых файлов через те же виртуальные
инструменты, что на сервере. Она не получает доступ к произвольным файлам
компьютера. В браузере показываются этапы, обращения к инструментам, ожидание
API, результат и технические ошибки. Счётчик ожидания не является текстом
внутренних рассуждений модели.

Анонимный ID тестировщика действует до завершения локального приложения.
После перезапуска приложение выдаёт новый ID; ключ подписи cookie хранится
только в памяти и не создаёт файл `.identity-secret`. Серверная версия
по-прежнему сохраняет свою подпись между перезапусками.

## Конфигурация и ключ

Ключ допускается только внутри конечного исполняемого файла. Не помещайте его
в `.env`, `botai-local.json`, исходники, текстовые файлы, сборочные каталоги
или журналы. Программа не читает `.env` проекта. Ключ в исполняемом файле
можно извлечь; передавайте такую программу только человеку, которому
разрешено пользоваться ключом.

Необязательный `botai-local.json` рядом с программой содержит только публичные
параметры:

```json
{
  "model": "deepseek-v4-flash",
  "timeout_seconds": 360,
  "max_output_tokens": 16000,
  "extra_body": null
}
```

Допустим `base_url` со значением `https://api.deepseek.com` или
`https://api.deepseek.com/v1`; оба варианта используют официальный API.
Другие адреса запрещены, чтобы проверка не попала обратно в шлюз.
Без встроенного ключа доступен запуск `--mock`, который проверяет интерфейс
и ход обработки без обращения к модели. Его результат не является настоящей
оценкой работы ученика.

## Запуск из исходников

Нужны Python 3.14 и зависимости из `requirements.txt`. Из корня репозитория:

```sh
.venv/bin/python scripts/run_local.py --mock
```

На Windows:

```bat
.venv\Scripts\python.exe scripts\run_local.py --mock
```

Для автоматизированных проверок есть `--no-browser`, `--port` и `--workspace`:

```sh
.venv/bin/python scripts/run_local.py --mock --no-browser --port 8765 --workspace /path/to/workspace
```

Рутинные проверки из исходников выполняются с mock. Реальный
платный вызов требует отдельного запроса пользователя, как указано в
[AGENTS.md](../AGENTS.md).

## Сборка Windows и macOS

Сборка выполняется на целевой ОС: Windows создаёт `.exe`, macOS — нативный
исполняемый файл. PyInstaller не является кросс-компилятором; для macOS
Intel и Apple Silicon нужны соответствующие сборки. Совместимость с версией
macOS зависит от ОС и Python, использованных для сборки.
[Документация PyInstaller](https://pyinstaller.org/en/stable/usage.html).

На macOS:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-local-build.txt
.venv/bin/python scripts/build_local.py
```

На Windows в командной строке:

```bat
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-local-build.txt
scripts\build_local.cmd
```

По умолчанию результат находится в
`dist/BotAI-Local-<система>-<архитектура>/`, рядом создаётся ZIP.
Параметр `--output` выбирает новую или пустую выходную папку; существующую
сборку инструмент не перезаписывает. В ZIP сохраняются исполняемые права
`Start.command` и пустые папки остальных номеров.

Сборщик не принимает и не читает ключи. Он упаковывает Python, исполняемый код,
зависимости и четыре разрешённых файла `app/static/`. Внешняя рабочая папка
содержит только семь утверждённых промптов, README и манифест SHA-256.
Промпты копируются побайтово. Студенческие фото, evals, гипотезы, скрытые ответы,
прочие Markdown-файлы, `.env` и пользовательская конфигурация не входят в сборку.
Символические ссылки в разрешённых входных файлах отклоняются.

Ключ добавляется отдельным шагом непосредственно в конечный исполняемый файл
из памяти. Запустите в интерактивном терминале и введите ключ в скрытом
приглашении; в командной строке самого ключа нет:

```sh
.venv/bin/python scripts/embed_local_key.py dist/BotAI-Local-darwin-arm64/BotAI-Local --scan .
```

Скрипт поддерживает несколько исполняемых файлов в одной команде. Для macOS
нужны macOS и установленные сборочные зависимости: он снимает прежнюю
подпись, добавляет данные в конечный файл, исправляет границы Mach-O на месте
и выполняет ad-hoc подпись. Windows `.exe` можно дополнить ключом на macOS.
SHA-256 в соседнем `manifest.json` обновляется автоматически.

Повторная проверка читает ключ только из готовой программы в память:

```sh
.venv/bin/python scripts/embed_local_key.py dist/BotAI-Local-darwin-arm64/BotAI-Local --scan . --verify-only
```

`--scan` можно повторить для нескольких папок. Проверка сообщает число
проверенных файлов и совпадений вне явно перечисленных конечных программ,
не выводя ключ. После добавления ключа не создавайте архив, копию или
промежуточный файл с ключом. Предварительный ZIP остаётся сборкой без ключа.

В репозитории есть workflow
[build-local.yml](../.github/workflows/build-local.yml): Windows x64, macOS
Apple Silicon и macOS Intel. Он создаёт только сборки **без ключа** и
запускается вручную через `workflow_dispatch` или при обновлении ветки
`codex/local-direct-app`. Наличие файла workflow
не означает, что Windows-сборка уже выполнена или проверена. Названия
macOS runners проверяются по
[документации GitHub](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Приложение не имеет публичной подписи разработчика и notarization. macOS или
Windows могут показать системное предупреждение при первом открытии.

## Офлайн-проверка

```sh
LLM_PROVIDER=mock LLM_VISION_PROVIDER=mock .venv/bin/python -m pytest tests/test_local_build.py
```

Тесты сборки проверяют точный список файлов, сохранение байтов промптов,
отсутствие приватных соседних файлов, отказ на символические ссылки и
содержимое ZIP. Нативную программу проверяет отдельный smoke-тест:

```sh
.venv/bin/python scripts/smoke_local_build.py dist/BotAI-Local-darwin-arm64/BotAI-Local
```

Он запускает программу с `--mock --no-browser`, проверяет режим, прямой адрес
API, семь промптов и доступность интерфейса. Затем отправляет два синтетических
PNG из памяти, проверяет оценку, сохранение OCR и рецензии, валидацию и точное
совпадение итогового JSON с сохранённым ответом, после чего останавливает процесс.
Workflow выполняет эту проверку на каждой платформе. Визуальную проверку
формы и отправки работы нужно выполнить в браузере отдельно.
