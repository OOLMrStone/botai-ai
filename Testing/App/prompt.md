# Запусти три локальных кабинета BotAI

Этот файл можно целиком передать агенту без истории чата. Выполни запуск и проверку,
а не только перескажи команды. Работай в клоне **botai-ai, ветка main**.
Разрешены только ветки `main` и `develop`; для независимой проверки используй
отдельный клон с detached HEAD. Не создавай другие ветки.

## Что здесь находится

- `Testing/App/frontend/` — настоящий Next.js frontend трёх кабинетов.
- `Testing/App/backend/` — Java backend, миграции PostgreSQL, хранилище Garage,
  PDF renderer и скрипты локального стенда.
- `app/`, `tasks/*/prompts/`, `tasks/common/prompts/` в корне репозитория — AI-сервис
  и действующие промпты. Они экспортируются в контейнер из **этого же клона**.
- `Testing/evals/14` … `Testing/evals/20` — существующие eval-наборы с изображениями,
  manifest и скрытыми эталонами. Старые пути `tasks/N/evals` оставлены ссылками.
- `Testing/App/run.py` — запуск, проверка, показ локальных аккаунтов и остановка.

Другие репозитории, приватная папка основателя и его Docker volumes не нужны. Все зависимости устанавливаются из lock-файлов/описаний образов.
Локальные пароли генерируются на машине пользователя. История чужих проверок
не копируется: здесь создаются новые тестовые работы.

## Требования

macOS или Linux. На Windows используй **WSL2 Ubuntu + Docker Desktop с интеграцией
WSL**, клонируй в файловую систему Linux (`~/botai-ai`), команды выполняй в WSL.
Нативный PowerShell этим launcher не поддерживается. Git должен создавать
символические ссылки; обычный Linux/WSL/macOS клон это делает.

Нужны Git, Python **3.10+** (для launcher, без pip-пакетов), Node.js **22+**, npm,
работающий Docker Desktop/Engine с Compose v2. Java и Python 3.14 для сервиса
собираются внутри Docker, на хосте они не требуются. Предусмотри примерно
8 ГБ памяти Docker и 15 ГБ свободного места для образов и зависимостей.
Первой сборке нужен интернет. Нужен доступ GitHub к репозиторию BotAI.

Проверь: `git --version`, `python3 --version`, `node --version`, `npm --version`,
`docker info`, `docker compose version`. Используй локальный Docker context
с Unix socket. Не переключайся на удалённый Docker/production.
Не выводи `docker inspect` окружение или полный Compose config: там пароли.

На macOS системный `python3` может быть 3.9. Если установлен `uv`, используй
`uv run --no-project --python 3.14 python Testing/App/run.py up` и тот же префикс
для остальных команд launcher. Либо установи актуальный Python и вызывай его
явно (`python3.14`). Не используй Python 3.9 и не заменяй системный Python.

## Первый запуск

```bash
git clone --branch main https://github.com/OOLMrStone/botai-ai.git
cd botai-ai
python3 Testing/App/run.py up
```

Если клон уже есть, начни с `cd botai-ai`. Launcher требует чистый Git checkout,
чтобы зафиксировать точную версию AI. Существующие изменения не сбрасывай:
сохрани их коммитом или используй свежий клон. Не запускай `git clean`,
`reset --hard`, `down -v` и не удаляй старые Docker volumes.

Команда создаст приватный runtime, экспортирует AI с общим OCR и Specialties,
соберёт и запустит backend/AI/БД/S3/PDF/Mailpit, добавит тестовые аккаунты и
пример с зачёркнутым π, установит npm-зависимости и запустит frontend.
Оставь терминал открытым. Первая сборка может занять несколько минут.

| Кабинет | URL | Вход |
| --- | --- | --- |
| Ученик | http://student.localhost:13004/school | Алексей Смирнов |
| Эксперт | http://expert.localhost:13004/grade | Мария Орлова |
| Проверки ИИ | http://dev.localhost:13004/grade/dev | аккаунт Марии Орловой |

Пароли выведи **в своём интерактивном терминале**, не вставляй их в чат/issue:

```bash
python3 Testing/App/run.py credentials
```

Также они находятся в `Testing/App/backend/runtime/b2b-local/credentials.json`.
Почты: `alexey.smirnov@math.example` и `maria.orlova@math.example`.
Это вымышленные локальные аккаунты. Поддомены нужны для раздельных cookies.
Если браузер не разрешает `*.localhost`, добавь только на своей машине:
`127.0.0.1 student.localhost expert.localhost dev.localhost` в hosts.
Не заменяй все три адреса одним localhost при проверке разных ролей.

## Проверка полного пути без оплаты модели

Во **втором терминале**, из корня клона:

```bash
python3 Testing/App/run.py verify
```

Проверяется настоящий HTTP-путь: вход ученика → создание работы → прикрепление
исходного решения ФИПИ → очередь → **mock AI** → черновик эксперта → подтверждение
→ опубликованный результат ученику; проверка доступна также в dev-журнале.
Проверяются роли, защита скрытого ответа, CSRF и соответствие запущенных образов.
Скрипт отказывается отправлять работу в live-режиме. Повтор после успешного
прохода проверяет сохранённый результат, а не создаёт очередную работу.
Квитанция: `backend/runtime/b2b-local/partner-mock-verification.json`.

Затем открой все три адреса в браузере. Убедись, что загрузились данные, а не
только шапка/индикатор. В ученике выбери №14 и карточку
**«ФИПИ 13.3.2 — сокращение π»**. Кнопка прикрепления примера использует локально
подготовленные фотографии; можно загрузить своё изображение или PDF.
В кабинете эксперта проверь открытие фото, редактирование записи/анализа,
сохранение черновика, ручную оценку, пересчёт оценки и подтверждение. После
подтверждения результат появляется у ученика; отправленная работа неизменяема.
Для следующего эксперимента создай новую попытку. В dev-кабинете можно запускать
новые проверки с собственными условием и решением для номеров **14–20**.

Начальный школьный каталог содержит один воспроизводимый пример 13.3.2.
Остальные evals уже лежат в `Testing/evals/`: их можно загружать через dev-кабинет,
но они не импортируются автоматически в школьный каталог. Личные фотографии,
которые раньше были только на компьютере основателя, не публикуются в Git.

**Mock проверяет работоспособность приложения, но не читает почерк и не оценивает
математику.** Его текст и балл демонстрационные. Для реального исследования OCR
нужно включить live ниже. Не выдавай успешный mock за исправленное зачёркивание.

## Реальная модель

Для партнёра подготовлен отдельный приватный архив `BotAI-Partner-Key.zip`.
После клонирования распакуй его **в корень botai-ai**: ключ должен оказаться в
`Testing/App/secrets/provider-key.json`. Этот путь игнорируется Git и не мешает
проверке чистого checkout. Ключ предоставлен владельцем для реальных тестов;
свой API-ключ в этом случае не нужен. Содержимое файла не выводи в чат или логи.
Сначала выполни `up` и `verify`, затем команду включения live ниже.
Само наличие ключа не включает платные запросы до этой команды.


После успешного `verify` пользователь может явно включить оплачиваемые проверки:

```bash
python3 Testing/App/run.py enable-live --accept-paid-requests
```

Команда автоматически импортирует переданный ключ из `Testing/App/secrets/`.
Если файла нет, попросит ключ DeepSeek скрытым вводом. Ключ сохраняется только
в игнорируемой приватной папке; AI/backend пересоздаются. Используется
`deepseek-flash`. Само включение не
отправляет запрос модели. Последующие «Проверить» / «Выставить оценку» в UI
могут списывать средства. Агенту запрещено выполнять платные прогоны без явного
запроса пользователя. Ошибка OCR на 13.3.2 известна и пока не исправлена.

Вернуться в mock можно **когда нет активных проверок**, сохраняя все работы:

```bash
cd Testing/App/backend
python3 scripts/b2b-local/provider-mode.py disable-live --apply
cd ../../..
```

Не меняй `.env` вручную для переключения режима. Обычный restart не применяет
новое окружение контейнера. После обновления кода или промптов нужна пересборка
и новая верификация, а не только перезапуск frontend.

## Повторный запуск, остановка, обновление

Ctrl+C в первом терминале останавливает frontend. Backend продолжает работать.
Для возобновления только сайтов (включая уже включённый live):

```bash
python3 Testing/App/run.py frontend
```

Остановить backend с сохранением данных:

```bash
python3 Testing/App/run.py stop
```

В mock-режиме повторный `up` пересобирает/поднимает службы и сохраняет данные.
Он отказывается незаметно выключать live или заменять экспорт другой версии AI.
Если после `git pull --ff-only origin main` изменился AI HEAD: сначала при
отсутствии активных работ явно вернись в mock; затем из `Testing/App/backend`
выполни `prepare-ai.py --source ../../.. --approved-head NEW_FULL_SHA
--archive-existing-head OLD_FULL_SHA` (скрипт лежит в `scripts/b2b-local/`).
NEW_FULL_SHA — `git rev-parse HEAD`, OLD_FULL_SHA — поле `approvedHead` приватного
`runtime/b2b-local/ai-approval.json`. Старый экспорт будет сохранён в истории.
После этого запусти `up` и `verify` снова. Для установки новой версии frontend
выполни `HUSKY=0 npm ci` в `Testing/App/frontend`. Не удаляй БД ради обновления.

При занятом порте не убивай чужой процесс. Узнай владельца или используй профиль
изолированной проверки ниже. Логи backend:
`cd Testing/App/backend && scripts/b2b-local/compose.sh logs --tail 100 backend ai`.
При ошибке изучи её и исправь причину; не подменяй API mock-фронтендом.

## Независимая проверка на машине с уже работающим стендом

Используй свежий отдельный клон и добавляй `--instance partner-check` к **каждой**
команде launcher:

```bash
python3 Testing/App/run.py up --instance partner-check
# Во втором терминале:
python3 Testing/App/run.py verify --instance partner-check
```

Этот профиль использует frontend **13014**, API **18096**, Mailpit **18037**,
отдельный Compose project `botai-b2b-local-partner-check`, отдельные volumes
и папку `backend/runtime/b2b-local-partner-check`. Кабинеты имеют те же поддомены
и пути, но порт 13014. Cookies привязаны к hostname, не порту: при одновременной
проверке двух стендов используй отдельный профиль браузера, чтобы вход в один
не сбросил сессию другого.

Если вызываешь backend-скрипты напрямую, добавляй
`B2B_LOCAL_INSTANCE=partner-check` перед **каждым** Python/compose.sh вызовом.
Не вызывай обычный `start.py`/`stop` для другого профиля. После проверки останови
только этот профиль; текущий 13004 не трогай. Сохрани краткий отчёт: commit SHA,
команды, URL, что реально проверено, ошибки и ограничения. Не публикуй пароли,
фото личных учеников, ключи, дампы БД или содержимое runtime.
