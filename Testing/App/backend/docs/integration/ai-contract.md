# Backend ↔ AI: контракт для общей спецификации

Контракт FROZEN v1.1, 2026-10-05; internal AI slice реализован и проверен локально. Прочитаны AI `AGENTS.md`, `docs/grading/service.md`, действующие service/session/provider/validator/package, integration WORKLOG/security/frontend/data/clean-architecture/SPEC. Server deployment и полный browser→backend→AI smoke этим документом не подтверждаются.

## Подтверждённые границы

- Единственный рабочий пакет — project №16, неравенства, ФИПИ-2026 №15, максимум 2. `package.SUPPORTED_TASKS={16}`; validator требует 16/2/score∈{0,1,2}. Папки 14/15/17/18/19/20 содержат только `.gitkeep`; legacy criteria не доказывают поддержку новым pipeline.
- Текущий `/api/v1/photo-check` — standalone: OCR фото условия/ответа → test IDs → Session. Новый путь пропускает только подготовительный OCR: backend уже предоставляет immutable task snapshot из БД.
- Канонический фактический deadline — **360 секунд** (`PhotoSettings`, provider, route); устаревшие 480 в `docs/grading/service.md` исправлены. Provider использует `max_retries=0`. Никаких provider probe для capabilities.

## Внутренний HTTP-контракт v1

- `POST /internal/v1/grading`: синхронный HTTP между worker и AI; асинхронность для браузера обеспечивает очередь backend. Единственный маршрут для всех extended номеров 14–20; никаких browser cookies, account/user IDs, DB/S3 credentials, внешних URL, features, criteria или model overrides.
- `Authorization: Bearer <INTERNAL_GRADING_TOKEN>`; constant-time comparison до чтения multipart. `INTERNAL_GRADING_ENABLED=false` по умолчанию; enabled без непустого token запрещает запуск. Неверный/отсутствующий token → 401. Private ingress; между хостами TLS. Секрет не передаётся модели и не логируется.
- `X-Request-ID` — UUID текущего run, проверяется и возвращается; backend хранит связь run → submission → owner. Все остальные ID ниже — UUID серверных task/version/image entities, без PII и путей.
- `multipart/form-data`: ровно один текстовый part `metadata` (UTF-8 JSON, ≤512 KiB) и 1–4 binary parts с одинаковым именем `solution_images`; порядок файлов соответствует `solution_image_ids`. Оригинальные filenames не используются.
- Точный `metadata` (другие/дублирующиеся ключи запрещены):
```json
{"contract_version":"photo-grade.v1","task_version_id":"<uuid>","task":{"id":"<task uuid>","task_number":16,"max_score":2,"statement":"<DB statement>","reference_answer":"<DB answer>","reference_solution":null},"solution_image_ids":["<image uuid>"]}
```
- `task.id` — canonical task ID; `task_version_id` остаётся transport metadata и не добавляется в `task`/промпт. Все поля обязательны; `reference_solution` — непустая строка либо null. Statement/answer: непустые ≤16 000 символов каждый; solution ≤32 000; task_number/max_score — строгие integers, не bool. IDs фото уникальны, их число равно числу файлов.
- Generic request parser допускает 14–20; max_score сверяется с registry/frozen taxonomy. Unsupported capability → 422 `unsupported_task` до provider, не модельный отказ. Номер вне registry/неверный snapshot → 422 `invalid_task_snapshot`; несовместимый contract_version → 422 `unsupported_contract`.
- Лимиты: общий поток ≤33 MiB, в том числе без Content-Length; каждый файл ≤8 MiB, JPEG/PNG/WebP, ≤20 MP, сторона ≤8192, статичный. Backend очищает metadata/re-encodes, AI повторяет `sanitize`; URL/PDF/SVG/анимация не принимаются. File/body/count caps действуют до model call.
- `200 application/json` + `Cache-Control: no-store`: **точный raw JSON**, прошедший `Session.finalize`, без envelope и пересериализации. Каждый ответ run, включая errors, несёт `X-Grading-Contract-Version: photo-grade.v1`, `X-Grading-Provider-Mode: mock|live`, `X-Grading-Package-Id: <selected digest>|none`; `none` означает, что рабочий пакет не выбран. Metadata фиксируется для данного run, не выводится backend из cached capabilities; unknown/missing/mismatched headers запрещают принятие grade. Request/run/version/capability metadata не добавляются в тело.
- Точная схема тела — [`SCHEMA`](../../../botai-ai/app/grading/validator.py) и [response-format](../../../botai-ai/tasks/common/prompts/response-format.md): только `task, solution_image_ids, is_graded, rejection_reason, ocr, analysis, grading`, все обязательны; дополнительные поля запрещены, включая вложенные.
- Graded: `rejection_reason=""`, `ocr:string`, `analysis` текущей полной структуры, `grading={score:int,criterion:string,explanation:string}`. Rejected: `is_graded=false`, непустая русская причина, `ocr=analysis=grading=null`; `task` и ordered image IDs неизменны. Единственный балл; никакого преобразования в base/presentation.
- Опциональный transport header `X-Grading-Rejection-Code`: `other_task|multiple_tasks|unrelated|attack|unreadable`, только из server Session, при отказе. Не выводить его из русского текста модели. Он не меняет validated JSON и не является пользовательской инструкцией.
- Errors: `{"error":{"code":"...","message":"<safe Russian text>","details":{}},"request_id":"<run uuid>"}`. 401 `service_unauthorized`; 400 `upload_disconnected`; 413 `upload_too_large`; 429 `grading_busy`; 422 `invalid_request_id|invalid_multipart|invalid_task_snapshot|unsupported_contract|unsupported_task|validation_error`; 502 `llm_error|llm_bad_response`; 503 `grading_package_changed`; 504 `llm_timeout`; 500 безопасный internal/config error. Error не содержит grade, provider body, PII или содержимое multipart; rejection header сохраняется и при обработанном сбое после set_rejection. Неверный route/method → 404/405, без redirect.

## Все номера подключены, capability честная

- Реестр AI содержит descriptors для **14,15,16,17,18,19,20**: `task_number,max_score,package_id,package_available,supported,response_contract,handler_factory,validator_factory`. Шкала общей taxonomy `draft2027`: **14:2,15:3,16:2,17:2,18:3,19:4,20:4**; источник проверен архитектором общей SPEC в [проекте ФИПИ-2027](https://doc.fipi.ru/ege/demoversii-specifikacii-kodifikatory/2027/ma_11_2027.zip), спецификация §10. Это шкала экзамена, не свидетельство поддержки AI; legacy registry не используется.
- Только16: approved package + existing Session/ValidationGate factories; остальные: package_id/factories=null, package_available=false, supported=false. Наличие директории не включает capability; startup проверяет комплект approved файлов и связанный validator.
- `GET /internal/v1/grading/capabilities` под тем же token возвращает объект с обязательными полями `contract_version:"photo-grade.v1", provider_mode:"mock"|"live", deadline_seconds:360, max_solution_images:4, max_image_bytes:8388608, tasks:Descriptor[]`; ровно7 descriptors, по возрастанию номера. Wire `Descriptor={task_number:int,max_score:int,package_id:string|null,package_available:bool,supported:bool,response_contract:"photo-grade.v1"}`; factories наружу не выдаются. Package ID — digest утверждённого комплекта. Это локальная конфигурация, не provider readiness probe.
- Backend объединяет capabilities со своей taxonomy; неизвестная/недоступная capability fail-closed. Browser получает server capability, не AI URL/token. Будущий утверждённый handler регистрируется только в AI: та же ручка и shape, backend проверяет dynamic max_score из pinned descriptor, UI читает capability; без переписывания front/back routing.
- Extension seam — выбор handler/validator по trusted registry, а не пользовательскому пути или имени файла. №16 продолжает вызывать **тот же** validator и Session; их поведение и утверждённые prompts остаются неизменными. Новый пакет/новый validator в этой работе не разрабатываются; несовместимый output shape требует новой версии контракта.
- UI показывает «Проверка этого задания пока недоступна», сохраняет фото/попытку и статус unsupported без оценки. При mixed exam проверяются доступные items; unsupported не считается нулём/неверным ответом или solved. Short-answer позиции 1–13 проверяет backend, не этот AI endpoint.

## Reuse, доверие и отчёты

- `run_prepared(task,image_ids,images,report_sink)` и standalone `run(task_image,...)` используют общий `_run_session`; standalone сохраняет свой PREP_PROMPT. Prepared path не создаёт test IDs и не запускает task OCR; provider создаётся после всех preflight проверок и закрывается в finally.
- Сохранить пакет main/OCR/analysis/catalog/grading/criteria/response-format, ADAPTER, read order, Notes без балла, tool allowlist, review-before-unreadable, revalidation после записи и exact finalize. DB statement/reference — данные, как фото/OCR/Notes; hidden eval answers не передаются. Нет filesystem/network/database tools.
- Existing `ReportStore.save(user_id,...)` принимает только `test-image-*` и пишет фото; подстановка UUID сломает attack branch. Сохранить этот sink для standalone. Internal sink держит per-run diagnostic и пишет bounded security event `{run_id,solution_image_ids,reason:"attack"}` без user_id/фото; rejection code передаётся header. Backend связывает собственные owner/photos и сохраняет submission event; AI не получает БД/S3.
- Если HTTP outcome потерян, backend сохраняет unknown outcome; correlation event остаётся по run ID, нельзя придумывать полученный отказ. В internal режиме нет дубля student photos в локальном AI ReportStore. set_rejection/ранние отказы не отключаются.
- Backend сохраняет exact response text/hash, отдельно проверяет strict schema, task snapshot целиком, ordered IDs, max/range, graded/rejected consistency и per-run provider/package headers. Public feedback — только OCR/analysis/grading projection; raw JSON с task/эталонами доступен лишь storage/admin, reveal — отдельный owner-authorized endpoint только для graded input. JSONB не сохраняет exact text; score никогда не clamp.

## Очередь и повтор

- Durable JSON intent → очищенные uploads → finalize с expectedRevision и без staged uploads → frozen snapshot + QUEUED/outbox/event одной транзакцией. Worker claim/lease/fencing, bounded concurrency, затем HTTP вне DB transaction; перед отправкой durable DISPATCHING/run ID через CAS по claimed state, fencing и unexpired lease; failed CAS запрещает HTTP.
- Lease покрывает upload + AI deadline + transport margin либо продлевается heartbeat. После crash/timeout/потери связи после dispatch — unknown outcome без автоматического replay. Auto-requeue допустим только доказанно до dispatch; явный retry создаёт новый run. AI v1 stateless, run ID — correlation, не гарантия exactly-once inference.
- Timeout/error/rejection/unsupported не создают нулевой балл. Conditional acceptance по run/fencing и unique result исключает двойной progress; поздний ответ после cancel остаётся audit event. Закрытие браузера не отменяет server job.
- `X-Grading-Provider-Mode=mock` явно маркирует синтетический результат в backend/public DTO и не даёт production progress, даже если cached capabilities раньше сообщали live. Mode/package берутся из обязательных headers **этого** ответа, сохраняются вместе с run; офлайн интеграционный контур использует только mock.
