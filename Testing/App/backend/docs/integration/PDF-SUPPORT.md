# PDF решений - согласованная архитектура

Исходные ограничения: текущий AI принимает только 1..4 изображения по <=8MiB. Backend Java21, Docker UID10001/read-only, tmpfs128MiB, memory768MiB; PDF parser/render dependency отсутствует. Existing images, canonical solution_image_ids и AI contracts/prompts сохраняются.

## Хранение и API

V17 additive: private solution_documents для исходного PDF и durable conversion state; stored_objects остаётся источником JPEG для AI, добавляются source_document_id/page_number. Original <=8MiB сохраняется byte-for-byte с SHA256, MIME application/pdf, отдельный случайный S3 key; никогда не входит в images/AI. 1..4 страниц совокупно с фото; весь PDF отклоняется при превышении, без first-N truncation.

`POST /api/submissions/{id}/documents` multipart file ->202 Document `{id,fileName,mimeType,sizeBytes,sha256,state,revision,pageCount,pages,errorCode,downloadUrl}`. Существующий upload images не меняет форматы. Accepted PDF state processing, короткая транзакция резервирует original и все remaining image slots staged; finalize блокируется staged pages; failed PDF возвращает 409 pdf_failed до удаления документа. Background worker конвертирует/S3 uploads вне DB tx; complete CAS проверяет draft/owner enabled/baseRevision/reservation, атомарно делает document и все страницы ready, revision+1. Никаких partial ready pages. GET submission включает documents[] и pages в прежних images с sourceDocumentId/pageNumber. Для JPEG документов metadata original PDF не придумывается.

`DELETE /api/submissions/{id}/documents/{documentId}` удаляет группу (original+pages) только в draft. Удаление PDF-derived image через прежний DELETE images также удаляет всю группу. Все staged/ready/planned keys регистрируются до upload; failed/stale/cancelled/crash reservations становятся delete_pending, reaper удаляет original/children повторно без пропусков. Concurrent photos/PDF не превышают общий budget. Processing jobs после crash не вызывают AI; stale lease будет cleanup, повторная загрузка явная.

Expert full work: images[] остаётся JPEG страницами, дополняется sourceDocumentId/pageNumber; documents[] содержит настоящий PDF metadata + ordered pages + private downloadUrl. `GET /api/expert/works/{workId}/documents/{documentId}` требует current school/expert/assignment и exact submission ready document. Owner download отдельным submission-scoped route. Download: application/pdf, Content-Disposition attachment, private/no-store, nosniff, CSP sandbox; raster pages - основной portable preview. Generic public/signed storage URL и inline-original под app origin не вводятся. Grade-only по-прежнему отправляет только analysis + OCR block IDs, PDF в AI не уходит.

## Isolated renderer boundary

Renderer - отдельный контейнер/процесс без DB/S3/service secrets, без Internet egress/host port, private network только backend+renderer, read-only, tmp128MiB, memory512MiB, concurrency1, deadline45s. PDF parser никогда не работает в API JVM. Dependency PDFBox3.0.8 только renderer (official PDFBox security требует sandbox/resource limits); encrypted/invalid/JS/actions/XFA/embedded attachments отвергаются, статические Ink/FreeText appearances сохраняются. Page geometry finite/rotation/UserUnit проверяются до allocation; RGB white JPEG sequential <=4096 side/6MP/page, total<=24MP, <=8MiB/JPEG.

`POST /internal/v1/pdf/render`, application/pdf raw bounded8MiB, `X-Request-ID: UUID`, `X-Max-Pages: 1..4` (reserved remaining budget). 200 Content-Type application/vnd.botai.pdf-pages, echoed request ID. Response framed binary: uint32 BE manifestLength<=16KiB; strict UTF-8 JSON manifest `{contract_version:"pdf-raster.v1",request_id,pdf_sha256,page_count,pages:[{page_number,width,height,size_bytes,sha256}]}`; затем для каждой страницы uint32 BE jpegLength + JPEG bytes, без trailing bytes. Page numbers exact1..page_count, count<=requested max; manifest/input hashes и sizes проверяются, total<=32MiB+16KiB+20. API повторно проверяет/decode-cleans только JPEG через существующий ImageNormalizer; никаких filenames/paths/ZIP/base64 на этой границе.

Renderer errors: 422 typed invalid/encrypted/active_content/page_budget/geometry; 429 busy; timeout/503 renderer_unavailable. Ни одна ошибка не оставляет partial ready metadata. Admission: 1 active PDF/user, 6 attempts/minute, <=8 queued+running, 1 global leased conversion; lease5min, uploaded-never-claimed queue TTL45min, original upload TTL10min. Expired lease fails/cleans instead of automatic retry. Cancellation tombstones retained/reconciled15min and worker finally repeats deletion of every planned key after lost fence, including already-deleted metadata; late S3 puts cannot leave ready pages. Network/render никогда под DB locks. Frontend source не меняется backend-агентом. Runtime ownership renderer/image/compose после security agreement; backend ownership V17/storage/jobs/DTO/routes/tests.
