## Корректировка эталона 13.3.2 — 21.10.2026

По запросу пользователя повторно проверена вся страница 24 исходного `matematika_mr_ege_2026.pdf`, пример 13.3.2. В [expected.json](../evals/fipi/13.3.2/expected.json) балл изменён с 1 на **2**; исходные балл и комментарий сохранены как `fipi_score` и `fipi_verdict`. Это локальная корректировка eval, а не утверждение об официальном исправлении документа ФИПИ.

Решение пункта а: `sin x(cos 2x + 1) + √2 cos²x = cos²x(2sin x + √2) = 0`. Получены все три серии: `π/2 + πk`, `−π/4 + 2πn`, `−3π/4 + 2πm`, параметры целые. Для отрезка `[3π/2; 3π]` записанные двойные неравенства дают соответственно `1 ≤ k ≤ 5/2` (k = 1, 2), `7/8 ≤ n ≤ 13/8` (n = 1), `9/8 ≤ m ≤ 15/8` (целых m нет). В ответе стоят ровно `3π/2, 7π/4, 5π/2`. В первой цепочке π сокращены; значения k и корней согласованы. Ошибки в нахождении n, на которую ссылается печатный комментарий, в работе нет.

По [критерию 2 баллов](../prompts/criteria.md) обоснованно получены верные ответы в обоих пунктах. Отнесение этого примера к E12 снято только в исследовательской таблице; рабочие промпты не менялись. Корректировка также сохранена в [verdict-overrides.json](../evals/fipi/verdict-overrides.json) с основанием `expert_override`; текущий OCR reading-key синхронизирован по баллу. При повторной нарезке передавать `--verdicts tasks/14/evals/fipi/verdict-overrides.json`: генератор использует `score: 2` и сохраняет `fipi_score: 1`. Исходник по-прежнему содержит 1 балл; оригинальный комментарий дополнительно хранится в override. Исторические результаты прогонов не пересчитывались и остаются свидетельством прежней разметки.

## Решения и открытые вопросы

- **Решено 30.09:** «ФИПИ всегда важнее». Правило задания 16 «две вычислительные ошибки → 0» не переносится; E15 повторяет формулировку ФИПИ «из-за вычислительной ошибки».
- **Решено 30.09 (спор агентов):** строка «Не ошибка» про неточность записи сужена до «все вычисленные значения верны» — ФИПИ-2025 пример 18.1.1 (опечатка при верных рассуждениях — максимум); ошибка в самой промежуточной выкладке по Указаниям ФИПИ-2022 — не максимальный балл.
- **Решено руководителем 30.09** (ответы на PDF с вопросами):
  1. Серия без указания множества параметра — ошибка: нет обоснования, что утверждение с введённой переменной верно. Если хотя бы где-то в решении указано, что параметр целый, — не ошибка. → E09 (раздел пункта а).
  2. Перебор, остановленный на корне, совпавшем с концом отрезка, — 1 балл: границу нужно явно показать тем, что за неё нельзя выйти. → E11.
  3. Вычислительную ошибку отличать от ошибки применения формулы: `8^(1/2) = 4` — вычислительная (формулы нет, число возведено в степень неверно) → пример в E15; знаменатель 2 вместо 2a — неверная формула, ученик её не знает → E04.
  4. Отбор без окружности с одной проверенной границей — необоснованный. → E11 (вместе с перебором: «не показаны обе границы»).
- **Следующий шаг:** evals — нарезать 22 работы 2026 года (с. 14–36) в `evals/fipi/` по образцу задания 16 и добавить мои работы старого №13 (А, В, Г, Е, Ж, З, X1–X3, X7, P14, P15).

Сохранённый OCR по-прежнему содержит `π ≤ k ≤ 5π/2`, без зачёркиваний
и подписанной единицы. Анализ пометил строку как недочёт; итог 2/2.
Следовательно, совпадение балла с исправленным эталоном не подтверждает

потеряны штрихи при чтении полос или при сведении; нужны промежуточные ответы.
Приватные артефакты сохранены в `botai-back/runtime/b2b-local/ocr-test-13.3.2-*`.

По решению пользователя удалена целиком строка «Дроби и смешанные числа в двойных неравенствах» из `ocr_specialties.md`: формулировка признана непонятной. Её влияние на предыдущий ошибочный OCR не установлено. Это правка исходного промпта; локальный runtime этим действием не обновлялся, новый модельный прогон не выполнялся.

Локализация по сохранённому прогону без новых модельных вызовов:
- Исходное фото получено через API кабинета эксперта и повторно обработано штатными `sanitize` и `strips`. На второй полосе (2400×1126) видны штрихи и подписанная единица; проблемная строка внутри полосы, а не на стыке. Обработка изображения их не удаляет.
- В `grading_results.exact_response` этой попытки уже записано `π ≤ k ≤ 5π/2`; обозначений `cancel` и `~~` нет. Следовательно, потеря предшествует преобразованию ответа backend и отображению в кабинете.
- `_layout` переносит строки расшифровки дословно через `line_ids`; валидаторы TeX проверяют запись без переписывания. Место потери — OCR до раскладки по шагам: чтение полос, сведение либо разрешение отмеченных сомнений, если оно вызывалось. Промежуточные ответы не сохранены, поэтому конкретный вызов и причина ошибки модели пока не установлены.
- Воспроизведённые изображения сохранены приватно в `botai-back/runtime/b2b-local/ocr-local-diagnosis/`. Следующая проверка требует OCR-прогона с сохранением каждого промежуточного ответа; совпадение итогового балла недостаточно.
