# JSON для экрана эксперта — решения Васи (голосовое 15.10.2026, 21:18–22:53)

Ответы на вопросы Кости и Claude по прототипу «Кабинет эксперта».

## Решено

1. **Шаги и их тип даёт чтец** (разбивка решения на шаги, тип шага из фиксированного списка). **Статусы шагов ставит анализ** — только он знает, верно ли.
2. **Статусы:** верно, ошибка, следствие ошибки, **недочёт** (отдельный статус). У одного шага — **одно замечание**, не несколько.
3. **Точки на прямой — по порядку, не в масштабе.** Нужно нарисовать не только точки, но и **дуги, которые нарисовал ученик, со знаками**.
4. **Спорного прочтения в итоговом JSON быть не должно.** Спорные места снимаются независимыми вызовами (3 голоса, 2 из 3) ещё на этапе чтения; отдельного поля для спорного прочтения нет.
5. **JSON — минимальный**, без лишних полей: ровно то, что нужно, чтобы нарисовать экран. Ориентир — прототип (скилл Васи).
6. **Числовая прямая:** у каждой точки — `id`, значение, включена ли в ответ (закрашена/выколота); дуги соединяют точки по `id` и несут знак. **Знак — только текстом `+`, `-` или `0`** (не «plus», не другие слова).
7. **Окружность** (задание 14) — аналогично: точки с `id`, значение, включена ли; дуги по `id`.
8. **Скрипт-валидатор** (Python), который проверяет:
   - на этапе чтения задана разбивка на шаги в едином формате;
   - результат чтения (OCR) **не меняется** на следующих этапах;
   - на этапе анализа у каждого шага проставлен статус из списка;
   - все форматы валидны (знаки только `+`/`-`/`0` и т.п.);
   - итоговый JSON собран честно: OCR в нём тот же, что выдал чтец.
   Если скрипт находит нарушение — нейросеть переделывает.
9. **Сроки:** завтра (16.10) — результаты нейросети и подсчёт стоимости (сколько запусков — Вася посчитает цену); **к пятнице 16:00** — рабочие 14 и 15 (и 16) с этим JSON. Попробовать перенести подход 14 на 16 с улучшением показателей (сделано: ФИПИ 20/21). Разобраться, почему модель занижает (15, 19).
10. Если будет время в ночь на пятницу — ещё одна задача (стереометрия 15).

### Предложение: типы шагов по номерам

| Номер | Типы шагов |
| --- | --- |
| 14 уравнение | condition, odz, substitution, transform, solve, back_substitution, selection, answer, other |
| 15 стереометрия | condition, construction, proof, computation, answer, other |
| 16 неравенство | condition, odz, substitution, transform, solve, intervals, back_substitution, selection, answer, other |
| 17 экономика | condition, model, transform, computation, solve, answer, other |
| 18 планиметрия | condition, construction, proof, computation, answer, other |
| 19 параметр | condition, odz, substitution, transform, model, construction, critical, cases, answer, other |
| 20 числа | condition, example, proof, estimate, computation, answer, other |

Значения: condition — запись условия; odz — ОДЗ; substitution — замена; transform — преобразование; solve — решение простейшего уравнения или неравенства; intervals — метод интервалов; back_substitution — обратная замена; selection — отбор (корни на отрезке, учёт ОДЗ); construction — рисунок, построение, график; proof — доказательство; computation — вычисление; model — сведение задачи к уравнению, неравенству или системе; critical — критические значения параметра; cases — исследование случаев, число решений; example — пример; estimate — оценка; answer — ответ (у задач с пунктами — по шагу на пункт, пункт в `title`); other — другое.

Шаг может отсутствовать: замены нет — нет и шагов substitution и back_substitution. Тип вне списка своего номера валидатор не пропускает (`ocr_errors(ocr, task_number)`).
